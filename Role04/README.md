# Role04 · GUI·사용성 웹 앱

### 통합 백엔드 실행

```sh
python -m pip install -r Role04/requirements-search.txt
ollama pull qwen3.5:4b
# Ollama 앱 또는 ollama serve를 실행한 상태에서:
python Role04/scripts/serve_web.py --open-browser
```

서버가 `Role01/automation_code/file_watcher.py`의 감시·갱신 큐를 시작하고 종료 시 함께 정리합니다.
서버 시작과 파일 변경 시 `update_pipeline_integrated.py`를 실행합니다.
파일 목록 → 본문 추출 → Qwen 설명 → 프로젝트·Role·시간 분류 → 검색 인덱스 순으로 처리하며,
성공한 결과만 기존 데이터와 교체합니다. 실패 원인은 GUI의 갱신 작업 상태에 표시됩니다.
감시 프로그램을 별도로 실행할 필요가 없습니다.

`POST /api/search`는 Role01 검색 엔진의 `search_files()`를 호출합니다.
파일 목록과 검색 응답은 `metadata.csv`, `metadata_description_generated.csv`,
`metadata_classification_generated.csv`를 `file_id`로 연결합니다.
수동 project/role을 우선하고 확인이 필요한 자동 예측은 `classification`에 보존합니다.
설명·분류 CSV가 갱신되면 다음 조회부터 반영하며, 모델 인스턴스는 재사용합니다.

파일 등록 → 검색 → 결과·근거·관련 파일 확인 → 파일 미리보기 흐름을 구현한 브라우저 GUI입니다. 초기 PySide6 계획에서 웹 방식으로 전환했습니다.

## 팀원 실행 방법

설치 후 실행 파일은 **[GUI 실행 폴더](GUI%20실행/README.md)**에 모여 있습니다.

기존 GUI에 `Role01/search_engine.py` 기반 의미 검색 API를 연결했습니다. 서버와 GUI는 같은 주소에서 실행되고 기본 모드는 실제 검색입니다.

공유 브랜치: **`main`**. 기존 작업 폴더와 섞이지 않도록 새 폴더에 받는 방법입니다. Git과 Python 3.13을 준비하세요. macOS에서 실행을 검증했으며 Windows 명령과 실행 파일도 제공합니다. Windows 실제 실행은 아직 미검증입니다.

### 1. 코드 받기 · 공통

```bash
git clone --branch main https://github.com/eunkyo00/AI-X.git AI-X-GUI
cd AI-X-GUI
git fetch origin main
```

GitHub 저장소 접근 권한이 필요합니다. 실행에는 프로젝트 전체 파일이 필요하며, 현재 준비 스크립트는 Git 이력을 읽지 않고 최신 Role01 파일을 점검합니다.

### 2. 설치·첫 실행 · macOS/Linux

저장소 루트(`AI-X-GUI`)에서 실행합니다.

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r Role04/requirements-search.txt
.venv/bin/python Role04/scripts/prepare_search.py
.venv/bin/python Role04/scripts/serve_web.py --open-browser
```

### 2. 설치·첫 실행 · Windows PowerShell

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r Role04/requirements-search.txt
.\.venv\Scripts\python.exe Role04/scripts/prepare_search.py
.\.venv\Scripts\python.exe Role04/scripts/serve_web.py --open-browser
```

패키지는 환경 준비 때, 검색 모델은 첫 검색 또는 인덱싱 때 다운로드합니다. 서버가 준비되면 브라우저가 열리며 첫 검색은 모델 준비로 시간이 더 걸릴 수 있습니다. 이후 각자의 로컬 캐시를 재사용합니다. 코드·질문·문서는 외부 추론 API로 전송하지 않으며 검색은 자기 컴퓨터에서 실행합니다. 모델 로더가 온라인 업데이트 여부를 확인할 수 있습니다. 모델을 한 번 받은 뒤 오프라인 실행하려면 macOS/Linux에서 `HF_HUB_OFFLINE=1`을, PowerShell에서 `$env:HF_HUB_OFFLINE="1"`을 설정합니다.

`prepare_search.py`는 현재 `Role01/`의 검색·추출 파일을 점검합니다. GUI와 자동 갱신이 동일한 최신 CSV·인덱스를 사용합니다. 모델과 감시 설정·등록 원본 보관본은 로컬에 저장하며 Git에서 제외합니다.

기본 주소는 [http://127.0.0.1:5173](http://127.0.0.1:5173)입니다. 준비 완료 후 브라우저가 열리며 터미널을 유지하고 종료는 Ctrl+C입니다. `--port 5175`로 포트를 바꿀 수 있습니다.

- macOS: 준비 후 `Role04/GUI 실행/Context Search 실행.command`를 더블클릭합니다. 저장소 `.venv`를 우선 사용합니다.
- Windows: 준비 후 `Role04/GUI 실행/Context Search 실행.cmd`를 더블클릭합니다.
- 모델 없이 예전 예시·브라우저 보관 화면만 실행: `python3 Role04/scripts/serve_web.py --demo --open-browser`.
- 다른 API 서버 사용: 설정에서 데이터 모드와 API 주소를 변경합니다. 내장 API는 동일 출처 전용입니다.

### 현재 통합 범위

실제 검색·파일 목록·메타데이터·유사도 점수·검색 본문 발췌를 제공합니다. 검색 엔진의 결과 순서를 유지하고 점수는 정확도 백분율로 변환하지 않습니다.

기본 샘플 데이터는 **158개 파일**이며, 등록·삭제에 따라 대상 수가 달라집니다. 기본 검색 예시는 `SARIMA 예측 코드`, `교차 검증 방법을 설명한 강의자료`, `갑오개혁의 전개와 성과`입니다.

내장 API는 파일 등록 뒤 자동 분석·DB/검색 인덱스 갱신과 폴더 변경 감지를 지원합니다. 원본 파일 다운로드와 PDF 미리보기를 지원합니다. OS 저장 폴더 열기·관련 파일 관계 API는 제공하지 않습니다. 브라우저 보관 모드는 별도로 사용할 수 있습니다. 내용이 있는 검색어에는 관련성이 낮아도 최대 5개가 반환될 수 있습니다.

검색 엔진 준비 후에는 `/api/health`, `/api/files`, `POST /api/search`를 제공합니다. [실행 검증 기록](docs/search-engine-validation.md)을 참고하세요.

## 파일 등록 후 자동 갱신 · 폴더 변경 감지

프로젝트 최상위의 Python 환경을 사용하면 기존 추출·검색 의존성을 그대로 사용합니다.

```sh
.venv/bin/python Role04/scripts/serve_web.py --open-browser
```

이미 켜 둔 서버는 종료한 뒤 다시 실행해야 새 API가 적용됩니다. 팀 환경 준비에는 기존처럼
`pip install -r Role04/requirements-search.txt`를 사용할 수 있습니다.
기본 엔진은 `Role01/`의 최신 데이터입니다. `prepare_search.py`도 이제 이 구성을 점검하며,
과거 커밋을 runtime에 복사하지 않습니다. 별도 `--engine-dir`을 지정한 읽기 전용 엔진에는 자동 등록이 활성화되지 않습니다.

- **파일·폴더 선택 → 선택한 파일 등록:** 전체 선택 파일을 한 작업으로 등록하고 자동 분석합니다.
  파일당 25MB, 한 번에 500개·총 100MB까지 지원합니다. 지원 형식은 PDF, CSV/TSV, XLSX,
  DOCX, PPTX, 텍스트·Markdown·JSON·Python·R·노트북 등입니다. 이미지 단독 검색은 지원하지 않습니다.
- **원본 폴더 자동 감지:** 파일 등록 화면의 ‘폴더 변경 자동 감지’에 이 PC의 폴더 전체 경로를 입력합니다.
  브라우저 폴더 선택은 파일 사본만 제공하므로 지속 감시할 원본 경로는 별도로 지정합니다.
  원본은 읽기만 하며 `Role01/dataset/files/watched/`의 전용 보관본에 변경을 동기화합니다.
- 서버 실행 중 약 1초마다 확인하고, 저장이 잠잠해진 뒤 약 2초 후 갱신합니다. 연속 변경은 묶고,
  분석 중 새 변경은 다음 작업으로 넘깁니다. DB·인덱스·설정 파일을 다시 감지하는 반복 갱신은 없습니다.
- 감시 폴더의 파일 삭제는 보관본과 다음 DB·검색 갱신에 반영됩니다. 폴더 자체가 사라지거나
  접근 불가하면 기존 보관본을 유지하고 오류를 표시합니다. ‘감시 해제’도 보관본은 유지합니다.
- 감시 설정과 마지막 반영 상태는 `.auto-refresh/`에 저장하고 재시작 시 이어서 감지합니다.
  서버가 꺼져 있을 때의 변경도 다음 실행 때 반영합니다. 원본 수정 시각·크기로 변경을 감지하며,
  내용만 바꾸고 두 값을 모두 그대로 보존하는 특수한 변경은 감지하지 못할 수 있습니다.
- 현재는 변경된 파일만 재처리하는 방식이 아니라 기존 전체 갱신을 호출합니다. 분석용 사본으로
  파일을 고정하므로 처리 중 원본이 바뀌어도 결과가 섞이지 않으며, 다음 작업에서 다시 반영합니다.
- 새 이미지형 PDF에는 기존과 같이 OCR 도구가 필요합니다. 분석 실패 시 기존 DB·인덱스는 유지하고,
  등록 화면에 실패 원인을 표시합니다. 갱신 완료 후 목록과 현재 검색 결과가 자동으로 새로고침됩니다.

GUI 담당자용 계약·검증 항목: `docs/auto-refresh-handoff.md`.
