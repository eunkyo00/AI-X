## 기준과 변경

GitHub main `0c8259ada55820dbdd4ec0c2ef8fa09fff896437`의 Role01·02·03 및 update_data.py를 실행용 스냅샷으로 준비했다. 기존 GUI 화면과 팀원 작업 폴더를 유지했다. 현재 이 변경은 로컬 작업이며 GitHub에 push하지 않았다.

- 의미·생성일/수정일 검색을 최신 SearchEngine에 연결.
- Role01 관계 후보와 Role03 DB의 해결된 정적 참조를 catalog/relations로 변환. 관계 근거를 전달하며 같은 방향의 동일 관계는 확인된 참조를 우선한다.

- multipart 등록, 수정 시각 보존, 안정적인 신규 ID, 중복 감지, 백그라운드 작업 조회 구현.
- 팀 갱신 코드의 이전 추출 결과 경로 차이를 호환 실행기로 보완. 이전 추출 캐시 또는 감사 기록과 실제 원본 SHA-256이 일치할 때만 본문을 재사용.
- 별도 준비 폴더에서 본문·DB·인덱스·관계를 갱신하고 새 엔진 로딩을 검증한 뒤 적용. 이전 데이터 백업과 실패 업로드 분리 보관 구현.
- 최초 설치 및 평소 실행 파일 제공. 이미 실행 중인 서버 재사용, 빈 포트 선택, 데이터별 서버 중복 실행 방지.

1. `SARIMA 예측 코드`: 실제 상위 5건, 원본 열기 가능.

3. `2026년 10월 생성한 파일`: 반환된 5건 모두 created_at이 2026년 10월, 관련 파일 포함.

5. UTF-8 텍스트 `통합 검증 메모.txt` 등록 → F200 ID 예약 → 본문·DB·임베딩·관계 갱신 ready → 실제 의미 검색 결과에 동일 ID 등장 → 다운로드 바이트 일치 → 같은 파일 재등록 시 duplicate=true.

## 남은 한계

- Windows 실행 파일은 제공하나 실제 실행은 미검증이다. 팀 갱신기의 symlink 사용에 Windows 개발자 모드 또는 권한이 필요할 수 있다.
- 새 이미지/OCR 전용 문서는 검색 등록을 지원하지 않는다. 기존 OCR 텍스트만 원본 해시 일치 시 재사용한다.
- Role02 학습 분류기를 자동 적용하지 않는다. 기존 프로젝트·역할 라벨을 유지하고 미제공 항목은 알 수 없음으로 표시한다.
- GUI 갱신은 실행 데이터 갱신이며 GitHub 코드 자동 업데이트가 아니다.
- OS 폴더 열기는 미지원이다. 검색 점수 임계값으로 무관한 결과를 자동 제거하지 않는다.
- 정상 종료는 진행 중인 갱신을 기다린다. 강제 종료·정전 도중 다중 파일 교체의 완전한 원자성은 보장하지 않는다. 이전 데이터는 update_backups에 남는다.
