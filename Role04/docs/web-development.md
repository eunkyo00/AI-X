# Context Search 웹 개발

사용자 요청에 따라 GUI를 브라우저 기반으로 전환했다. 현재 파일 등록·보관·열기·API 연결 설정·사용성 기록까지 GUI를 확장했다. 2026-10-29부터 Role01 검색 엔진을 내장 API와 연결했다. 실제 의미 검색은 검증했고, 원본 열기·등록·DB·외부 사용자 평가는 대기다. 최신 범위와 검증 상태는 [GUI 인수인계](gui-handoff.md), 연결 규격은 [API 계약 초안](api-contract.md)을 참고한다.

## 실행

최신 설치·실행 명령과 Mac/Windows 안내는 [Role04 README](../README.md)를 따른다. 검색 모드에는 Python 가상환경·검색 패키지·데이터 준비가 필요하다.

예전 화면 전용 실행은 `python3 scripts/serve_web.py --demo`다. 검색 모드는 저장소 루트의 `.venv` Python으로 `Role04/scripts/serve_web.py`를 실행한다. 기본 주소는 `http://127.0.0.1:5173`, 종료는 Ctrl+C다. 포트가 사용 중이면 `--port 5175`를 추가한다.

## 구성

- `web/index.html`: 홈, 검색 결과, 상세 탭, 사이드바 메뉴
- `web/styles.css`: 시안에 맞춘 색상·타이포그래피·반응형 배치
- `web/app.js`: 화면 전환, 검색어 전달, 작업 예시 대화상자, 최근 검색 UI, 탭·키보드 조작
- `web/workspace-service.mjs`: IndexedDB 보관·API 어댑터·응답 정규화
- `web/workspace-ui.mjs`: 등록·내 파일·즐겨찾기·설정·미리보기·사용성 기록
- `web/history.mjs`: 최근 검색 저장·검증·중복 제거
- `web/search-data.mjs`: 화면용 예시 파일·관계·검색 시나리오와 필터·정렬 함수
- `web/search-view.mjs`: 결과 카드, 선택 상태, 필터, 상세 탭
- `web/search-service.mjs`: 비동기 MockSearchService, 요청 순서·취소·시간 초과를 관리하는 SearchController
- `scripts/serve_web.py`: Python 표준 라이브러리 로컬 웹 서버

프런트엔드는 HTML·CSS·JavaScript로 동작하며 Node 패키지 설치나 빌드가 필요 없다. Python 서버는 정적 화면과 `/api/health`, `/api/files`, `/api/search`를 제공한다. `scripts/search_api.py`가 Role01 엔진 응답을 GUI 형식으로 변환한다. 엔진은 검증한 커밋에서 `scripts/prepare_search.py`로 준비하며 원본은 수정하지 않는다.

## 현재 확인할 동작

1. 검색어 입력 후 Enter 또는 화살표 버튼으로 결과 화면 이동.
2. 추천 문구·검색 예시 카드 클릭으로 검색어 전달.
3. 결과 화면에서 질의를 수정하고 다시 검색.
4. 개요·검색 근거·관련 파일·작업 맥락 탭 전환. 탭은 방향키·Home·End 지원.
5. 사이드바 메뉴 이동, 홈 복귀, 브라우저 뒤로/앞으로 이동.
6. 빈 검색은 실행하지 않음. 검색어는 HTML로 해석하지 않고 텍스트로 표시.
7. 데스크톱의 3영역 배치를 작은 화면에서 축소·세로 배치로 전환.

## 2단계 홈 기능

- 추천 검색어 3개와 검색 예시 카드 4개를 클릭해 바로 검색한다.
- 검색창에 입력 안내·Enter 힌트·입력 지우기를 제공한다. 공백 검색은 실행하지 않는다.
- 최근 작업 3개는 **예시**로 표시한다. 선택 시 파일명·역할을 보여주고 예시 질문으로 검색할 수 있다. 더보기에서는 예시 작업을 선택한다.
- 최근 검색은 최신 8개를 localStorage에 보관하고 홈에는 4개까지 표시한다. 같은 질문을 다시 검색하면 맨 앞으로 이동한다.
- 최근 검색 전체 화면에서 재검색·개별 삭제·전체 삭제가 가능하다. 삭제는 이 앱의 검색 기록만 지운다.
- 검색 시각을 방금 전·분 전 등으로 표시한다. 화면을 다시 열 때 갱신한다.
- 저장소 사용이 제한되면 현재 방문 중 메모리 기록으로 동작하고 화면에 안내한다.
- 데스크톱은 사이드바·중앙·최근 활동 3영역이며 작은 화면에서는 최근 활동을 아래에 배치한다.

최근 검색은 이 브라우저의 이 사이트 주소에만 저장되며 서버로 전송하지 않는다. 같은 브라우저에서 주소·포트를 바꾸면 다른 기록 공간을 사용한다. 파일 등록·열기는 브라우저 로컬 보관과 API 어댑터로 구현했다. 실제 AI 인덱싱과 팀원 서비스 통합은 미연결 상태다.

## 3단계 검색 결과 기능

- R 과제, Python 실습, 딥러닝 발표·논문 시나리오에 따라 서로 다른 예시 결과를 표시한다. 총 12개 파일이며 실제 검색 엔진이 아니다. 무관한 질문은 0건을 표시한다.
- 결과 카드에서 형식·작업·역할·수정 날짜·경로·요약 근거를 확인한다. 순위는 예시 추천 순서이며 확률이나 정확도 퍼센트를 표시하지 않는다.
- 전체·문서·데이터·코드·이미지·발표자료 필터와 수정 날짜 필터를 함께 적용한다. 날짜는 명시된 연·월 기준이다.
- 추천순·최신 수정순·이름순으로 정렬한다. 정렬해도 원래의 추천 순위는 유지한다.
- 첫 결과를 자동 선택한다. 목록에서 다른 파일을 선택하면 상세 내용이 바뀐다.
- 개요에서는 파일 정보·주요 근거·직접 연결된 관련 파일을 보여준다. 각 상세 탭에서 전체 근거, 관계, 작업 구성을 확인한다.
- 확인된 참조와 추정을 라벨로 구별한다. 수정 시각은 실제 사용 시각과 다를 수 있으며 코드의 저장 구문을 실행·생성 사실로 단정하지 않는다.
- 관련 파일이나 작업 맥락의 파일을 클릭하면 해당 상세로 이동한다. 현재 필터 밖의 파일이면 관련 파일에서 선택한 항목이라고 표시한다.
- 필터 0건에서는 조건 초기화를, 검색 자체가 0건이면 지원 예시 질문을 안내한다. 0건에서는 이전 파일 상세를 비운다.
- 새 검색은 기존 필터·정렬·선택을 초기화한다. 모바일에서 파일을 선택하면 아래 상세 영역으로 이동한다.
- 파일 열기 버튼은 실제 로컬/API 파일을 미리보기한다. 예시 파일이면 실제 원본이 없다는 안내를 표시한다.

브라우저에서 파일 선택·근거·관련 파일 이동·작업 맥락·필터 0건·초기화·최신순 정렬·검색 0건을 확인했다. 데이터 로직과 기존 검색 기록 검증은 다음 명령으로 수행한다.

```bash
node --test tests/test_web_history.mjs tests/test_web_search.mjs
```

화면은 파일 ID를 기준으로 선택과 관계를 연결한다. 실제 서비스 연결 시 검색 어댑터와 관련 파일·작업 메타데이터 공급자를 함께 교체해야 한다. 현재 관계와 작업 정보는 화면용 예시 파일에 연결되어 있다.

## 4단계 예시 서비스와 예외 처리

검색 결과 화면 상단에서 **예시 응답 설정**을 펼친다. 응답을 선택한 뒤 **현재 검색어로 확인**을 누르거나 검색창에서 다시 검색한다. 선택만으로 진행 중인 요청이 바뀌지는 않으며 다음 요청에 적용된다. 새로고침하면 정상 응답으로 초기화된다.

| 선택 | 응답과 확인할 화면 |
| --- | --- |
| 정상 응답 | 약 0.35초 후 해당 시나리오의 예시 결과 |
| 결과 0건 | 질의와 관계없이 빈 목록과 안내, 이전 파일 상세 초기화 |
| 응답 오류 | 오류 안내와 정상 응답 재시도 버튼 |
| 느린 응답 (4초) | 약 4초간 검색 중 표시, 새 검색·중단·화면 이동 가능 |

- 검색을 시작하면 이전 결과·상세를 비운다. 응답 대기 중에는 필터·정렬을 비활성화하고 검색어 수정은 허용한다.
- 검색 중단은 예시 서비스의 타이머까지 중단한다. 중단 후 다시 검색할 수 있다.
- 오류·중단 화면의 **정상 응답으로 다시 시도**는 응답 설정을 정상으로 변경하고 마지막으로 제출한 질문을 재요청한다. 수정만 하고 제출하지 않은 입력으로 바꾸지 않는다.
- 새 검색은 이전 요청을 취소하며 요청 버전도 검사한다. 서비스가 취소를 무시하더라도 이전 성공·오류가 새 화면을 덮어쓰지 않는다.
- 다른 메뉴나 홈으로 이동하면 진행 중 요청을 중단한다.
- 10초 동안 응답이 없으면 요청을 중단하고 재시도를 안내한다. 기본 예시 서비스는 최대 4초이므로 시간 초과는 제어기 테스트에서 검증한다.
- 모든 응답은 브라우저 안에서 만들어진다. 실제 네트워크·AI 검색·파일 읽기를 수행하지 않는다.

서비스 경계는 `search(query, { scenario, signal }) → Promise<{ files, source }>`다. `scenario`는 예시 전용 옵션이고 `signal`은 AbortSignal이다. API 어댑터를 추가할 때도 Promise와 취소 신호를 유지하면 현재 검색 중·오류·중단·시간 초과 흐름을 활용할 수 있다. 현재 기본 응답 검사는 files가 배열인지 확인하며, 실제 API 연결 시 파일 필드·관계 데이터도 검증해야 한다.

검증 명령:

```bash
node --test tests/test_web_history.mjs tests/test_web_search.mjs tests/test_web_service.mjs
```

총 12개 테스트: 기존 검색·기록 6개와 정상/0건/오류/취소, 오래된 성공·실패 응답 차단, 화면 이동 중단, 응답 시간 초과와 복구, 잘못된 응답·공백 질의 처리를 검증하는 서비스 6개다. 브라우저에서도 정상 결과, 오류 복구, 강제 0건, 지연 중단, 진행 중 새 질의 전환을 확인했다.

검증: 브라우저에서 예시 작업 상세, 예시 질문 검색, 검색 기록 새로고침 후 유지, 개별·전체 삭제, 검색어 지우기, 공백 입력 차단과 반응형 배치를 확인했다. 저장소 모듈은 아래 명령으로 테스트한다(Node.js 필요).

```bash
node --test tests/test_web_history.mjs
```

테스트 범위: 최대 개수·중복 제거·저장 복원, 손상된 기록·잘못된 필드 처리, 저장 제한 시 동작과 다른 저장 키 보존.

웹 브라우저는 PC의 임의 경로를 직접 열거나 읽을 수 없다. 파일 등록 시 사용자 선택을 받고, 실제 파일 열기·저장 위치 열기는 팀의 로컬 백엔드와 연결하는 방식으로 설계해야 한다.

기존 PySide6 코드와 설치 확인 도구는 보존되어 있으며 웹 개발에 필요하지 않다. 기존 작업계획서의 기능·담당 범위는 유지하고 Qt 위젯·스레드 구현 항목은 웹 컴포넌트·비동기 API 호출로 대체한다. 공개 호스팅 없이 로컬 개발용으로 구성했다.


## 남은 GUI 구현과 실제 검증 구분

- 파일·폴더 선택/드롭, 형식·크기 검사, 진행 개수, 부분 실패·재시도 UI.
- 브라우저 IndexedDB에 실제 파일 보관. 로컬 등록 완료 시 보관 파일 모드로 전환. AI 분석·인덱싱 완료로 표시하지 않음.
- 실제 파일명·경로 검색, 읽기 전용 코드/텍스트·이미지·PDF 보기, 기타 형식 다운로드.
- 내 파일·즐겨찾기·작업 보기·설정 메뉴와 실제/예시 데이터 모드 구분.
- 설정의 팀원 API 주소, 요청 어댑터, metadata/relations 정규화, health·파일 계약 점검.
- 사용성 관찰 기록 저장·JSON 내보내기. 개발 점검은 실제 사용자 관찰에서 제외.
- 실제 OS 저장 폴더 열기, 실제 검색·DB 통합, 외부 사용자 3~5명 평가는 아직 검증 대기.

현재 검증 결과와 나머지 수동 확인 항목은 [gui-handoff.md](gui-handoff.md)에 기록했다. 형식별 파서·AI 모델·DB를 GUI에서 대신 구현하지 않는다.
