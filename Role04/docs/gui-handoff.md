# GUI 인수인계·시연·사용성 검증

최신 기준일: 2026-10-29. Role01 검색 엔진을 내장 HTTP API와 기존 GUI에 연결했다. 검색·파일 목록·본문 발췌를 검증했으며 원본 158개 열기·PDF 페이지·코드 미리보기·다운로드까지 연결했다. DB·새 파일 등록·파일 관계는 미연결이다. 실행 방법은 [Role04 README](../README.md), 상세 결과는 [검색 통합 검증](search-engine-validation.md)을 따른다. 아래 예전 시연 기록은 당시 범위의 기록이다.

## 모드

- 예시 시나리오: 기존 R/Python/발표 데모, 실제 파일 없음.
- 브라우저 보관: 사용자 선택 파일을 IndexedDB에 보관하고 파일명·상대 경로로 검색. AI 내용 추출·임베딩·검색 인덱싱을 수행하지 않음.
- 팀원 API: 설정한 서버로 검색어와 선택 파일을 전송. 미연결 시 오류로 표시하고 예시 결과로 대체하지 않음.

DB·검색·파서 구현은 팀원 책임이다. 브라우저 보관은 GUI 개발용이며 팀의 DB를 대신하지 않는다. 상대 경로·크기·수정 시각을 이용한 로컬 중복 검사는 내용 해시 검증이 아니다. 브라우저/사이트 주소가 달라지거나 사이트 데이터를 삭제하면 보관본을 사용할 수 없다.

## 실행

`Role04/GUI 실행/` 폴더의 `Context Search 실행.command`를 더블클릭한다. Mac의 터미널과 기본 브라우저가 열린다. 실행 권한 또는 보안 정책으로 실행되지 않으면 다음 명령을 사용한다.

```bash
cd AI-X/Role04
python3 scripts/serve_web.py --open-browser
```

서버 실행 중 터미널을 유지하고 종료는 Ctrl+C. 5173 포트가 이미 사용 중이면 기존 서버를 사용하거나 `--port 5174`로 실행한다. 포트를 바꾸면 브라우저 저장 데이터 공간도 달라진다.

새 환경: Python 3.10 이상과 저장소를 준비한다. 가상환경은 필수가 아니다. 웹 실행은 표준 라이브러리만 사용하므로 PySide6 설치는 불필요하다. 테스트는 Node.js 내장 테스트 러너를 사용한다.

```bash
node --test tests/test_web_history.mjs tests/test_web_search.mjs tests/test_web_service.mjs tests/test_workspace_service.mjs
```

## GUI 시연 약 3분

1. (30초) 예시 모드에서 R 과제 질의를 실행하고 결과·근거의 확인/추정을 설명한다.
2. (30초) 결과의 코드·관련 파일·작업 맥락을 이동하고 필터를 적용한다.
3. (30초) 예시 응답 오류를 선택한 뒤 정상 응답으로 재시도한다.
4. (45초) 파일 등록에서 TXT·CSV·Python 파일을 선택하고 로컬 보관한다. 보관 완료가 AI 검색 준비 완료와 다름을 설명한다.
5. (30초) 보관 파일 검색 모드에서 파일명의 단어로 검색하고 코드를 텍스트로 연다. 즐겨찾기를 확인한다.
6. (15초) 연결 설정에서 실제 서비스 미연결 상태와 통합 계약 문서를 보여준다.

테스트용 파일은 `tests/fixtures/gui-flow/`에 있다. 실제 사용자 개인정보 파일 없이 GUI 동작을 확인할 수 있다. 지원불가.bin은 실행 파일이 아닌 일반 테스트 본문이며 형식 거절 확인용이다.

## 사용자 점검 — 아직 미실시

개발자 외 3~5명에게 아래 과제를 설명을 최소화해 제공한다. 이름 대신 참가자 코드를 쓴다. 설정 → 사용성·시연 점검에서 실제 사용자 관찰/개발 점검을 구분해 기록한다. JSON은 로컬로 내보낸다. 자동 점검 기록은 사용자 평가 수에 포함하지 않는다.

| 과제 | 관찰 항목 |
| --- | --- |
| 파일 추가 | 파일/폴더 선택을 찾는가, 성공·실패를 구분하는가 |
| 파일 검색 | 모드와 검색 범위를 이해하는가, 0건에서 다음 행동을 찾는가 |
| 근거 확인 | 확인된 참조와 추정의 차이를 설명할 수 있는가 |
| 관련 파일 찾기 | 코드/입력 데이터/결과의 관계를 이동할 수 있는가 |
| 열기·경로 | 코드가 실행되지 않는다는 점과 상대 경로의 한계를 이해하는가 |
| 실패 복구 | 오류 안내로 재시도·설정 변경·등록 상태 확인을 수행하는가 |

기록 필드: 참가자 코드, 실제 관찰/개발 점검, 과제, 성공/도움 후 성공/실패, 소요 초, 막힌 위치, 의견. 실패는 UI/서비스/데이터 문제로 분류해 각 담당자에게 전달한다. 현재 실제 사용자 관찰은 0건이며 완료를 주장하지 않는다.

## 이번 검증에서 확인한 것

- Node 자동 테스트 19개(검색·관계·기록·비동기·API 계약·미제공 메타데이터·파일 허용 범위).
- 검증용 다중 파일 선택: 유효 3개 보관, 지원 불가 1개 구분.
- 보관 파일 검색, 새로고침 후 보관본과 즐겨찾기 유지.
- Python 파일과 HTML 형태 문자열의 읽기 전용 텍스트 보기, 미리보기 영역 script 요소 0개.
- API 서버 부재를 미연결로 표시, 사용성 개발 점검을 실제 사용자 관찰에서 제외.

현재 Mac의 연결 브라우저에서 확인한 결과다. 전체 브라우저/OS, 실제 API, 실제 검색 품질, 실제 사용자 평가가 검증됐다는 의미는 아니다.
