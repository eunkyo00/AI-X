# AI-X 개발 기록

AI-X는 “지난달 R 과제에 쓴 데이터”처럼 기억나는 상황을 입력해 파일과 관련 자료를 찾는 개인 검색 시스템이다.

**개발 흐름: 자료 정리 → 의미 검색 → 설명·시간·분류 추가 → 관련 파일 추천 → GUI·자동 갱신 통합**

기준은 2026-11-23의 `main` [6606aee](https://github.com/eunkyo00/AI-X/commit/6606aee277c154051d3d94be07842b85bed1a687)이다. 코드·보고서·평가 자료와 커밋 142개를 확인했다. 아래 날짜는 별도 표시가 없으면 커밋 기록일이며, 파일 이동과 반복 수정은 묶었다.

## 1. 프로젝트 개요

파일명과 위치를 몰라도 내용, 생성·수정 시각, 과목·파일 역할, 파일 간 참조를 단서로 자료를 찾는 것이 목표다.

사용 흐름은 다음과 같다.

**파일 등록 → 본문 추출·설명·분류 → DB·검색 인덱스 갱신 → 자연어 검색 → 결과·근거·관련 파일 확인 → 원본 열기**

| 영역 | 담당 기능 |
| --- | --- |
| Role01 — 검색 | 의미 검색, 시간·과목·역할 조건, 관련 파일 추천 |
| Role02 — 분류·평가 | 데이터·정답 구성, 과목·유형 분류, 설명 생성, 성능 평가 |
| Role03 — 파일 처리·DB | 파일 ID·메타데이터·본문 저장, 참조 추출, 데이터 품질 점검 |
| Role04 — GUI·통합 | 검색 화면, 파일 등록·열기, 백엔드 연결, 자동 갱신 |

주요 기술은 Python, E5 임베딩(문장의 의미를 벡터로 표현), 로지스틱 회귀, SQLite, Ollama/Qwen이다. 현재 GUI는 HTML·CSS·JavaScript와 로컬 Python 서버로 동작한다. 초기 PySide6 구상은 실제 웹 GUI와 구분한다. [프로젝트 소개](../README.md)

## 3. 역할별로 무엇을 개발했나

### Role01 — 검색과 관련 파일 추천

처음에는 파일 본문을 작은 조각으로 나누어 의미가 가까운 파일을 찾았다. 비슷한 강의·코드가 경쟁하고 동명 파일이 섞이는 문제가 있어 파일별로 결과를 묶고 파일 ID로 평가했다.

이후 검색 결과 재정렬을 시험했지만 평균 성능은 그대로였다. 파일 설명을 검색 입력에 추가한 실험은 효과가 있었고, 생성·수정일과 과목·역할 조건도 연결했다. 관련 파일은 **파일명 참조·폴더 → TF-IDF 내용 유사도 → E5 의미 유사도 → 복합 단서·동일 주차** 순서로 발전시켰다. 현재 V5는 직접 참조를 우선하고 내용·과목·역할·시간·폴더·주차를 함께 사용한다.

[검색 엔진](../Role01/search_engine.py), [관계 추천 V5](../Role01/file_relations_v5.py)

### Role02 — 분류와 평가

파일별 과목·역할·설명과 검색 질문·정답을 구성했다. 평가 중 파일명 중복과 오래된 정답 ID를 발견해 ID 기준 채점과 정답표 교정을 진행했다.

과목 분류는 E5와 로지스틱 회귀로 시작해, v3.1에서 본문·설명·파일명을 따로 활용하고 신뢰도가 부족한 파일을 `새 과목`으로 분리하도록 개선했다. 자료 유형은 6종으로 통일하고 규칙과 모델을 결합했다. 시간 정보는 수정일 등을 월·분기·계절로 바꾸며, Qwen 설명은 검색·분류에 활용했다. 기존 수동 라벨과 설명은 보존한다.

[과목 분류](../Role02/PROJECT_CLASSIFIER.md), [유형·시간 분류](../Role02/FILE_METADATA_CLASSIFIERS.md), [설명 생성](../Role02/description_generator.py)

### Role03 — 파일 처리와 DB

파일 ID·경로·시각·본문을 SQLite에 저장하고, Python·R·노트북·문서에서 파일 참조와 근거 위치를 추출했다. 참조는 **연결 확인·모호함·대상 미등록**으로 구분해 잘못된 연결을 줄였다.

품질 점검에서는 R 파일 36개의 크기 차이가 줄바꿈 때문임을 확인하고 TSV 2개의 본문을 복구했다. 이후 경로 정규화, 기존 ID 보존, 추출 상태 기록, 원본 해시 확인을 보완했다. 갱신 결과는 임시 공간에서 검증한 뒤 반영하고 실패 시 백업으로 복원한다.

[DB·참조 추출](../Role03/file_db.py), [품질 점검](../Role03/QUALITY_CHECK_REPORT.md), [통합 갱신](../update_data.py)

### Role04 — GUI와 시스템 통합

예시 검색 화면에서 시작해 실제 검색 API, 결과·근거·관련 파일, 원본 다운로드와 PDF 미리보기를 연결했다. 이후 파일 등록, 중복 감지, 처리 상태, 폴더 자동 연결을 추가했다.

## 4. 핵심 실험과 결과

### 검색: 재정렬보다 설명 추가가 효과적이었다

같은 158개 질문·정답 ID의 보존 결과다. Hit@5는 정답 파일이 상위 5개에 포함된 비율이다.

| 방식 | 성공 | Hit@5 |
| --- | ---: | ---: |
| 기본 의미 검색 | 129/158 | 81.65% |
| 상위 후보 재정렬 | 129/158 | 81.65% |
| 파일 설명 추가 | 158/158 | 100.00% |

재정렬은 성공·실패가 한 건씩 바뀌어 평균 개선이 없었다. 설명 추가는 내부 질문 집합에서 효과가 있었지만 독립 최종 평가 결과는 아니다. [재정렬 결과](../Role01/evaluation_results_rerank.csv), [설명 결과](../Role01/evaluation_results_description.csv)

시간 조건과 정답 ID를 교정한 결과는 **194질의 중 192개 성공(98.97%)**, 이 중 시간 질의는 **23/23 성공**이다. 이전 결과와 정답 ID가 171행에서 달라져 점수 변화를 시간 알고리즘만의 효과로 볼 수는 없다. [시간 검색 결과](../Role01/evaluation_results_time_fixed.csv)

### 분류: 기존 과목 선택과 신규 감지를 나누어 평가했다

| 실험 | 결과 | 의미 |
| --- | --- | --- |
| 기존 과목 분류 v3.1 | 158개·5-fold 정확도 100%, Macro F1 1.0 | 기존 5개 과목 선택 성능. 자동 확정은 148/158개 |
| 생성 설명 A/B | 신규 감지 34/41 → 39/41 | 기존 자동 확정은 149개 → 148개로 한 개 감소 |
| 자료 유형 분류 | 규칙 결합 후 정확도 89.87% → 91.14%, Macro F1 0.830929 → 0.850884 | 158개·4-fold에서 임베딩만 쓸 때보다 개선 |

신규 감지 실험은 빈 과목 라벨 41개를 모두 신규로 가정했고, 설명 조건마다 판정 기준도 다시 맞췄다. 실제 신규 과목 정답과 작업 단위 독립 검증은 추가로 필요하다. [과목 지표](../Role02/project_classifier_artifacts_v3/project_classifier_metrics.json), [설명 A/B](../Role02/DESCRIPTION_AB_EXPERIMENT.md), [유형 지표](../Role02/role_classifier_artifacts/role_classifier_metrics.json)

### 관계 추천: V5가 V4의 누락을 줄였다

검토 집합의 출발 파일 17개에 대한 결과다. Recall@5는 정답 관련 파일의 회수 비율, MRR@5는 첫 정답이 얼마나 앞에 나오는지 나타낸다.

| 버전 | 사용한 단서 | Hit@5 | Recall@5 | MRR@5 |
| --- | --- | ---: | ---: | ---: |
| V3 | 의미 유사도 | 0.8824 | 0.8431 | 0.8529 |
| V4 | 의미·과목·역할·시간·폴더·참조 | 0.9412 | 0.8137 | 0.7706 |
| V5 | V4에 동일 주차 추가·가중치 조정 | 0.9412 | 0.8725 | 0.8471 |

V4는 적중률이 높아졌지만 회수율과 순위는 나빠졌다. V5는 이를 보완했으나 MRR은 V3보다 조금 낮다. 같은 확정 정답으로 채점했지만 저장된 전체 대상은 V3/V4 202개, 최신 V5 204개로 달라 단서 하나만의 효과를 분리한 비교는 아니다. [관계 평가 요약](../Role01/relations_evaluation_summary.csv)

### 처리 속도: 변경 없는 파일을 재사용하도록 개선했다

초기에는 본문·임베딩을 전체 생성했다. 이후 파일 해시와 입력별 캐시를 도입했다. 203개 반복 갱신 로그에서는 본문·임베딩 모두 203개를 재사용했고, 목록·본문·설명·분류·인덱스 단계가 총 39.61초였다. DB·관계 생성은 별도 시간이며, 같은 조건의 전량 처리 측정이 없어 속도 향상 배수는 확인할 수 없다. [시간 로그](../update_timing.log)

## 6. 현재 상태와 남은 과제

기준 커밋의 저장 데이터는 **204개, 본문 추출 성공 204개, 정적 참조 197건, V5 추천 1,020건**이다. PDF·R·노트북·CSV·Markdown·Python·JSON·TSV·XLSX가 포함된다. GUI의 11/23 검증은 고정 백엔드의 **203개** 기준이므로 두 집계를 구분한다. [현재 처리 집계](../Role03/output/summary.json), [최신 GUI 검증](../Role04/docs/integration-2026-11-23.md)

문서 조사 시 DB·분류 로직·GUI 테스트 63개가 통과했다. 최상위 갱신 테스트는 21개 중 19개 통과·2개 실패로, 과거 배치 등록 API와 현재 GUI API의 계약 차이가 남아 있다. SQLite 무결성은 정상이다.

남은 과제는 다음과 같다.

- 데이터·질문·설정을 고정한 독립 최종 평가와 키워드 기준선 비교
- 실제 신규 과목과 주차 단서가 없는 파일의 분류·추천 검증
- Windows GUI, 외부 사용자 사용성, 최신 GUI의 신규 Qwen 설명 생성 검증
- 새 이미지·OCR 전용 문서 등록과 강제 종료 중 갱신 복구 보완

현재 과목별 묶음과 정적 참조를 제공하지만, 실제 파일 사용 이력이나 작업 세션 전체를 복원했다고 볼 근거는 없다.
