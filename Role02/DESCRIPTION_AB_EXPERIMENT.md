# description 포함 여부 비교 실험

## 실험 조건

- 입력: `Role02/test_output/metadata_description_generated.csv`와
  `Role01/extracted_text.csv`에 공통으로 존재하는 F001~F199
- 기존 프로젝트: 158개, 신규 프로젝트 표본: 41개
- 분류기: v3.1, Logistic Regression `C=10`
- 평가: 파일 단위 5-fold 교차검증
- 신규 프로젝트 판정 기준은 각 조건에서 별도로 재보정
- `TEST_NEW_001`은 추출 본문 데이터에 대응 행이 없어 비교에서 제외

## 결과

| 조건 | 기존 프로젝트 선택 정확도 | 평균 신뢰도 | 기존 프로젝트 자동 확정 | 신규 프로젝트 감지 | 신규→기존 오분류 |
|---|---:|---:|---:|---:|---:|
| description 제외 | 100.0% | 65.6% | 94.3% (149/158) | 82.9% (34/41) | 7개 |
| 생성 description 포함 | 100.0% | 72.2% | 93.7% (148/158) | 95.1% (39/41) | 2개 |

생성 description을 포함하면 평균 신뢰도가 6.6%p 높아지고 신규 프로젝트 감지율이
12.2%p 높아졌다. 기존 프로젝트 자동 확정은 1개 감소했지만, 신규 파일을 기존
프로젝트로 잘못 배정한 수가 7개에서 2개로 줄었다.

F001을 전체 기존 프로젝트 데이터로 학습한 실제 운영 모델에 입력하면 신뢰도는
description 제외 64.0%에서 description 포함 66.7%로 높아지고, 두 조건 모두
`딥러닝`으로 분류한다.

## 데이터 점검

- F001~F199의 생성 description은 기존 `metadata_description_merged.csv`와 전부 같다.
- 생성 description 199개에 빈 값이 없다.
- 기존 프로젝트 158개의 description에 정답 프로젝트명이 그대로 포함된 경우는 없다.
- description 생성기는 프로젝트 라벨이나 폴더 경로가 아니라 파일명과 추출 본문만
  입력으로 사용한다.

원시 수치는 `description_ab_experiment.json`에 저장했다.
