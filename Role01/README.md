# AI·검색

사용자의 상황 설명을 검색 조건으로 해석하고, 파일 내용·시간·역할·관계를 종합해 목표 파일과 관련 파일을 찾는 역할입니다. 검색 순위뿐 아니라 해당 파일을 추천한 이유도 함께 제공합니다.

## 주요 담당 업무

- 질의에서 작업 내용, 시간 범위와 찾는 파일의 역할을 분석합니다.
- 파일과 질의를 임베딩으로 변환하고 의미적으로 가까운 파일을 검색합니다.
- 의미·시간·역할·관계 점수를 결합해 검색 결과를 재정렬합니다.
- 관련 파일과 추천 근거를 GUI에서 표시할 수 있는 형태로 반환합니다.

## 협업 기준

- **파일 처리·DB**에서 추출 텍스트, 시간 정보, 파일 ID와 참조 근거를 받습니다. 임베딩과 벡터 검색은 AI·검색이 담당합니다.
- **데이터·평가**에서 개발·검증 질문과 실패 분석을 받으며, 검색 결과와 설정을 전달합니다.
- **GUI·사용성**에는 순위, 관련 파일과 추천 근거를 전달합니다. 확인된 참조와 추정 관계를 구분합니다.

## 데이터 갱신

프로젝트 최상위에서 최초 한 번 환경을 준비합니다.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

`Role01/dataset/files/`에 파일을 넣은 후 다음 명령 하나로 갱신합니다.

```sh
.venv/bin/python update_data.py
```

메타데이터 → 전체 본문 추출 → SQLite와 참조 근거 → 검색 임베딩 순서로 처리합니다.
Windows에서는 `.venv\Scripts\python.exe update_data.py`를 사용합니다.
작업 위치와 무관하게 실행 파일의 위치를 기준으로 데이터를 찾습니다.
과거 Windows 경로도 `dataset/files/` 아래의 상대 경로로 통일하며,
기존 경로의 ID·project·role·description 등 수동 입력 열은 보존합니다.
이동·이름 변경은 새 파일로 취급합니다. ID를 초기화하는 `file_inform.py`는 반복 갱신에 사용하지 않습니다.

새 결과는 임시 공간에서 준비하며, 추출 오류 또는 DB·검색 인덱스 생성 실패 시 기존 결과를 유지합니다.
미지원 형식과 빈 본문은 처리 상태로 기록합니다. 정상 반영 전 기존 결과를
`update_backups/`에 백업하며 반영 중 일반 오류가 나면 복구합니다.
여러 결과 파일을 교체하므로 전원 종료에 대한 완전한 원자적 저장은 보장하지 않습니다.
갱신 중에는 검색을 잠시 보류하며, 이미 실행 중인 검색도 다음 질의에서 새 CSV·인덱스를 확인합니다.

검색 실행:

```sh
.venv/bin/python Role01/refresh_search.py
```

첫 임베딩 모델 다운로드에는 인터넷이 필요합니다. 매번 전체 파일을 재추출·재임베딩합니다.
Role03의 과거 품질 점검 보고서와 `*_issues.csv`는 갱신하지 않으며,
새 처리 집계는 `Role03/output/summary.json`을 기준으로 확인합니다.
GUI 버튼과 변경 파일만 처리하는 최적화는 포함하지 않습니다.

기존 `search_model.py` 및 시간·설명·재정렬 평가 스크립트는 원격 main의 기능을 유지합니다.

최신 GUI의 의미 검색도 통합 인덱스를 읽고 다음 검색 요청에서 파일 목록을 갱신합니다.
시스템·기록 파일과 LICENSE, SOURCE.json 제외, ZIP에 보존된 생성 시각, TSV·PDF OCR 등
원격 main의 기능을 유지합니다. OCR에는 별도 Tesseract 설치 및 kor/eng 언어 데이터가 필요합니다.
실행 파일은 PATH 또는 `TESSERACT_CMD` 환경 변수로 지정할 수 있습니다.
OCR 도구가 없는 환경에서도 원본 SHA256이 동일하고 이전 추출이 성공했다면 기존 OCR 결과를 재사용합니다.
변경되거나 새로 추가된 이미지형 PDF에 OCR 도구가 없으면 갱신을 중단하고 기존 결과를 유지합니다.
