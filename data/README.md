# 데이터셋

로컬 파일 검색 기능을 개발하고 평가하기 위한 데이터셋입니다.

## 폴더 구성

- `raw/`: 검색 대상이 되는 원본 문서, 데이터, 코드와 결과물. ZIP 파일은 이 폴더에 올립니다.
- `labeled/`: 원본 파일의 역할·관계와 평가 질문·정답을 정리한 라벨 데이터

## 데이터 구성

- 작업별로 설명 문서, 입력 데이터, 코드와 결과물을 포함합니다.
- 비슷한 이름의 파일, 수정본과 무관한 파일을 함께 구성합니다.
- 파일명과 폴더명이 모호해도 내용과 관계로 검색할 수 있도록 구성합니다.

## 검색 대상 폴더 예시

아래는 `raw/`에 구성할 검색 대상 폴더의 예시입니다. 사용자가 상위 폴더 하나를 선택하면 하위 폴더까지 검색 범위에 포함합니다. `강의자료/`에는 과목별 하위 폴더 없이 여러 과목의 파일을 섞고, 관련 과제 결과물과 무관한 개인 파일을 함께 배치합니다.

```text
검색대상폴더/
├── 강의자료/
│   ├── lecture_05.pdf        # 파이썬 CSV 처리 강의
│   ├── lecture_05 (1).pdf    # 웹프로그래밍 강의
│   ├── lecture_03.pdf        # 교양수업 강의
│   ├── attachment.pdf        # 파이썬 과제 안내
│   ├── attachment (1).pdf    # 웹프로그래밍 과제 안내
│   ├── example.py            # 파이썬 실습 예제
│   ├── example (1).py        # 다른 주차의 파이썬 예제
│   ├── index.html            # 웹프로그래밍 실습 예제
│   ├── data.csv              # 파이썬 실습 데이터
│   └── presentation.pdf      # 교양수업 발표 자료
│
├── example (2).py            # 실습 예제를 수정한 과제 코드
├── data (1).csv              # 과제 코드에서 읽는 데이터
├── output.png               # 과제 결과 그래프
├── 과제보고서.pdf
├── 여행일정.pdf
├── 지출내역.csv
├── screenshot.png
└── 기타자료/
    ├── 동아리공지.pdf
    └── 메모.txt
```

`#` 뒤의 설명은 구성 의도를 나타내며 실제 파일명에 포함하지 않습니다. 이 구조는 데이터 구성 예시이며, 실제 파일이 준비되어 있거나 모든 형식의 분석이 구현되었다는 의미는 아닙니다.

이 예시로 같은 폴더의 서로 다른 작업을 구분하고, 다른 폴더에 있는 같은 과제의 코드·데이터·결과물을 연결할 수 있는지 확인합니다. 작업 관계와 검색 정답은 검색 대상 폴더 밖의 `labeled/`에 기록합니다.

## 라벨 정보

- 파일 ID와 원본 경로
- 소속 작업과 파일 역할
- 관련 파일과 관계 근거
- 평가 질문과 정답 파일

## 관리 기준

- 검색 인덱스에는 `raw/`의 파일만 포함합니다.
- `labeled/`는 검색 결과를 검증하는 정답으로 사용합니다.
- 원본 파일과 라벨은 파일 ID로 연결합니다.
- 개인정보나 공개 허가가 없는 파일은 업로드하지 않습니다.
- 합성 데이터와 임의로 설정한 시간 정보는 별도로 표시합니다.
